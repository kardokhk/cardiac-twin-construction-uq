# Construction-stage uncertainty in ECG-calibrated cardiac digital twins

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23771882.svg)](https://doi.org/10.5281/zenodo.23771882)

Code, analysis plan and result tables for a known-truth study of how the construction of a twin anatomy (segmentation network, mesh resolution, fast endocardial layer rule) changes conduction velocities calibrated to the electrocardiogram (ECG). Fifty test hearts of the Automated Cardiac Diagnosis Challenge (ACDC) are each built from expert labels and four public segmentation networks at 1.5 mm and 1.0 mm, simulated with the openCARP eikonal solver and an eight-lead lead-field ECG, and calibrated for endocardial and cross-fibre velocity against ECG targets simulated from known velocities. Three benchmarks give the construction spread a scale: ECG noise, simplified physics (reaction-eikonal targets) and a generic torso (22 heart-in-torso models).

Author: Kardokh Kakabra, RCSI University of Medicine and Health Sciences, Dublin, Ireland.

## Contents

| Path | What it holds |
|---|---|
| `plan/` | Dated analysis plan (method sections, 2026-10-22) and its two dated amendments (2026-10-28) |
| `code/gates/seg/` | Segmentation runs: nnU-Net (Task027, Task114, UK Biobank short axis), CineMA, ukbb_cardiac; Dice and HD95 |
| `code/gates/mesh/`, `code/full/mesh/` | Surface reconstruction, voxel meshing (1.5 and 1.0 mm), fibres, roots, fast endocardial layers (voxel-face and smooth-surface), mesh checks |
| `code/gates/ka/`, `code/pilot/I09/` | Known-answer checks: analytic slab and thick shell, N-version benchmark, lead-field reciprocity, ellipsoid layer volume |
| `code/full/calib/` | Emulator (spline surrogate of activation times plus kriging refinement), calibration of every construction, ECG-noise benchmark |
| `code/full/armF/`, `code/full/armT/`, `code/pilot/I13/` | Simplified-physics benchmark (reaction-eikonal targets) and generic-torso benchmark |
| `code/full/analysis/`, `code/manuscript/v03_analyses.py` | Estimands, mixed models, cluster bootstrap, break-even noise, per-network analyses |
| `code/figures/` | Figure scripts; `figures/source_data/` holds the values behind every plotted panel |
| `results/` | Result tables (CSV, JSON, Markdown) of every run, each directory with its README |
| `tests/` | Known-answer and regression tests |
| `environment.md`, `requirements.txt` | Software versions, seeds and the pinned Python environment |

In the code and plan, "arm C" is the construction experiment, "arm N" ECG noise, "arm F" simplified physics and "arm T" the generic torso.

## Inputs not redistributed here

- ACDC images and expert labels (CC BY-NC-SA 4.0): https://humanheart-project.creatis.insa-lyon.fr/database/
- Heart-in-torso models: Malik et al. 2026, doi:10.5281/zenodo.18890229; Qian and Bishop 2022, doi:10.5281/zenodo.7253863
- Network weights: nnU-Net Task027 (doi:10.5281/zenodo.4485926), Task114 (doi:10.5281/zenodo.4288464), UK Biobank short-axis model (doi:10.5281/zenodo.15649643); CineMA and ukbb_cardiac from their repositories
- Third-party source code (CineMA, MIT licence; ukbb_cardiac, Apache 2.0): `code/gates/seg/fetch_third_party.sh` clones the commits used (c10daa1d and f465832c)
- openCARP v20.0, doi:10.35097/wnkfjg829nnr380b

Derived masks, meshes and per-construction simulation files are regenerated by the pipeline; they are not included because of their size and the ACDC licence.

## Running

The pipeline was run on the MeluXina cluster (Slurm). Job scripts (`*.sh`, `*.sbatch`) contain site-specific account names and absolute paths under `/project/home/p201509`; adapt these to your system. Order of the main steps:

1. Segmentation: `code/gates/seg/seg_job.sh` (GPU), then `evaluate.py` and `summarise.py`.
2. Meshing: `code/full/mesh/full_build.sh`, `full_solve.sh`, `full_assemble.sh` (smooth-surface layer: `endo_layer.py`).
3. Known-answer checks: `code/gates/ka/ka.sbatch`.
4. Calibration and ECG noise: `code/full/calib/armC_job.sh`, `armC_sdf_job.sh`, `noise_ext_*.sh`, `export_job.sh`.
5. Benchmarks: `code/full/armF/armF_job.sh`, `code/full/armT/armT_v2_job.sh`.
6. Analysis: `code/full/analysis/analysis_job.sh`, then `code/manuscript/v03_analyses.py` and `derived_values.py`.
7. Figures: the scripts in `code/figures/`.

Tests: `python -I tests/test_v03_analyses.py` (plain runner; pytest is not required), plus the unit tests beside the code (`test_*.py`).
